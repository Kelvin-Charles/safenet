SafeNet RADIUS

Many business access points can send guests to an external login page and then check the code with a RADIUS server. SafeNet is both. Guests see your SafeNet login page with your packages, pay with mobile money or type a voucher, and SafeNet hands the code back to the access point, which checks it with SafeNet and lets the phone online.

Which devices work

BrandStatus

Huawei, Aruba, others🧪 Not tested yet. Follow the steps; if SafeNet doesn't recognise the device, the Sites page shows what it sent. Send that to support.
UniFiComing: UniFi lets guests online through its controller, which needs its own setup.

Your own internet address. The access point's RADIUS requests reach SafeNet from the site's internet address. SafeNet learns it by itself when the first guest opens the login page, so a changing address is fine. But some 4G/5G lines share one address between many customers. If SafeNet finds the address is shared with another SafeNet business, the Sites page tells you; then ask the provider for your own (public) IP, or use a SafeNet gateway or MikroTik.

1. Switch it on in SafeNet

  1. Open your siteIn SafeNet open Sites and click RADIUS next to the site.
  2. Switch it onClick Switch on RADIUS access points. SafeNet shows:
    External login page URL{{ public_url }}/hs/YOUR-SITE-CODE (yours is on the Sites page)
    RADIUS server{{ server_ip or public_host }}
    PortsAuthentication 1812, accounting 1813
    RADIUS secretshown on the Sites page (one for all your sites)
    Allow before login{{ public_host }}{% if server_ip %} and {{ server_ip }}{% endif %}
  3. Add packagesMake sure at least one package is sold at this site on the Packages page.

2a. Grandstream GWN

  1. Update the firmwareUse recent firmware on every access point (older ones lack the external splash page).
  2. Make a captive portal policyIn GWN.Cloud, GWN Manager or the master access point's web page open Captive Portal → Policy → Add. Splash page: External, with the external login page URL from SafeNet.
  3. RADIUSAuthentication: RADIUS, with SafeNet's server, port 1812 and the secret. Turn on accounting (port 1813, interim update 60 seconds).
  4. Pre-authentication rulesAdd {{ public_host }}{% if server_ip %} and {{ server_ip }}{% endif %} so phones can open the login page before they log in.
  5. Use it on the guest Wi-FiEdit the guest SSID: security Open, captive portal on, this policy.

2b. Cambium

  1. Guest accessIn cnMaestro (or the access point's page) edit the guest WLAN: Guest Access → Portal mode: External Hotspot, and the external login page URL from SafeNet as the splash page.
  2. RADIUSAdd SafeNet's RADIUS server for authentication (1812) and accounting (1813) with the secret.
  3. Leave "External Portal Post Through cnMaestro" offSafeNet sends the code to the access point itself.
  4. Walled gardenAdd {{ public_host }}{% if server_ip %} and {{ server_ip }}{% endif %}.

2c. CoovaChilli (OpenWrt)

Install coova-chilli on the router and set, in /etc/config/chilli (or /etc/chilli/config): uamserver = the external login page URL, uamallowed = SafeNet's address, radiusserver1 = SafeNet's RADIUS server, radiussecret = the secret. Leave uamsecret empty.

2d. MikroTik and Meraki

These keep their RADIUS setup from the MikroTik or other routers guide. To let guests buy on the login page too, send them to the external login page URL: on MikroTik from the hotspot's login.html (with link-login-only, link-orig and mac), on Meraki as the custom splash URL with "Sign-on with my RADIUS server".

3. Test it

  1. Join the Wi-FiWith a phone, join the guest Wi-Fi and open any website. Your SafeNet login page appears, and the Sites page shows Last guest sent by … and the internet address SafeNet sees.
  2. Log inMake a voucher (Vouchers → Generate) and type it. The phone gets online. Auth logs shows the access point's RADIUS check.
  3. Code accepted but no internet?The access point's RADIUS request didn't reach SafeNet, or the secret differs. Check the secret, that the access point uses port 1812, and the address on the Sites page.
